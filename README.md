# Building-site

Учебный проект: двое учатся работать в паре через Claude Code — git,
ветки, PR, разделение зон, документация. Предмет тренировки — лендинг
строительной компании.

**Сайт:** https://wnter288-svg.github.io/Building-site/

Делают двое: Тимофей (frontend) и Даня (backend + инфраструктура), каждый в
своём Claude Code, синхронизация через этот репозиторий.

---

## С чего начать

| Ты | Читай в таком порядке |
|---|---|
| Впервые в проекте (человек или ИИ) | `docs/PROJECT.md` → `docs/STRUCTURE.md` → `TODO.md` |
| Садишься работать | `docs/HANDOFF.md` → `docs/PROGRESS.md` → `TODO.md` |
| Правила работы в репозитории | `CLAUDE.md` |

## Запуск

Проект ещё не начат — стек не финализирован (предварительно Astro +
Node/Express, см. `docs/PROJECT.md`). Раздел заполняется, когда появится
код.

```
# frontend
cd frontend && npm install && npm run dev

# backend
cd backend && npm install && npm run dev
```

## Настройка машины (один раз после клонирования)

```bash
git config core.hooksPath .githooks
```

Включает хук, который не даст случайно запушить в `main`. **Обязательно
для обоих разработчиков** — без этой команды хук не работает, git её из
репозитория сам не подхватывает.

## Ветки

- `dev` — рабочая, сюда коммитим и пушим
- `main` — стабильная, только через Pull Request

```bash
git checkout dev
```

## Навыки Claude Code

В `.claude/skills/` лежат общие навыки — они подхватываются автоматически у
обоих разработчиков:

- `/project-docs` — привести документацию в соответствие с кодом
- `/project-structure` — проверить и почистить структуру проекта
- `/test-project` — прогнать тесты работоспособности и безопасности
- `/advisor` — рекомендации и запасные планы
