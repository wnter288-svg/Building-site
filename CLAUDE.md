# Что мы делаем

Нас двое, мы вместе делаем этот сайт. Каждый работает в своём Claude Code
на своей машине. Два Claude Code напрямую друг с другом не общаются и не
видят чужих сессий. Общаемся мы только через файлы в этом git-репозитории.

Git здесь - единственный источник правды. У каждого своя локальная копия
проекта, синхронизируемся мы через общий репозиторий на GitHub. То есть
функционально это одна общая папка, просто изменения переносятся через git.

Стек: **[ЗАПОЛНИТЬ - фронт и бэк, например React + Vite на фронте, Node
+ Express на бэке]**

# Кто за что отвечает

- **frontend/** - зона Тимофея
- **backend/** - зона Дани

Работай в своей зоне. Файлы в чужой зоне без явной причины не меняй. Если
кажется, что нужно тронуть чужую зону, сначала опиши это в docs/HANDOFF.md
и скажи об этом своему разработчику.

---

# Файлы для синхронизации между нами

Всё в папке docs/:

- **docs/API.md** - контракт между фронтом и бэком: список эндпоинтов,
  форматы запросов и ответов. Это шов, где две части встречаются. Пока
  контракт не меняется, каждый работает независимо.

- **docs/PROGRESS.md** - лог изменений. Кто, когда, что сделал. Только
  дописываем, ничего не стираем. Новые записи добавляй СВЕРХУ, чтобы мы
  сами не конфликтовали в этом файле.

- **docs/HANDOFF.md** - прямые сообщения второму разработчику. Например:
  "поменял формат ответа /login, обнови обработку на фронте". Прочитал
  сообщение и выполнил - удали его.

# Правила для тебя, Claude Code

## В начале каждой сессии
1. Сделай `git pull`, чтобы подтянуть изменения второго разработчика.
2. Прочитай docs/API.md - актуальный контракт фронт/бэк.
3. Прочитай docs/PROGRESS.md - что напарник сделал с прошлого раза.
4. Прочитай docs/HANDOFF.md - есть ли сообщения лично для нас.

## После каждого заметного изменения
1. Допиши запись в НАЧАЛО docs/PROGRESS.md в формате:
   `ГГГГ-ММ-ДД | [имя] | что изменил | что напарнику важно знать`
2. Если ты поменял контракт (эндпоинт, формат данных) или что-то, что
   затрагивает зону напарника - обнови docs/API.md и опиши изменение в
   docs/HANDOFF.md.

## Перед завершением работы
1. Сначала `git pull` (вдруг напарник что-то залил, пока мы работали).
2. Потом `git commit` с понятным сообщением.
3. Потом `git push`.
4. Если git ругается на конфликт - не решай молча. Покажи мне конфликт и
   предложи вариант решения.

# Коротко

Мы двое делаем сайт через два отдельных Claude Code. Синхронизация - через
git и три файла в docs/. Читай почту (API.md, PROGRESS.md, HANDOFF.md) в
начале, пиши в неё в конце, держи свою зону. Так мы всегда в курсе того,
что делает другой, и не мешаем друг другу.
