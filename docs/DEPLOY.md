# Деплой

Как код попадает на сайт.

**Хостинг:** Vercel. **Адрес:** будет выдан при первом деплое
(вида `dimora.vercel.app`), потом можно привязать свой домен.

---

## Как это работает

```
  работаем в dev  ──PR──►  main  ──автоматически──►  Vercel
```

Vercel сам собирает проект при попадании в `main` и публикует. Пуш в
`dev` на прод ничего не выкатывает — в этом смысл разделения веток.
Для каждого PR Vercel дополнительно поднимает превью-ссылку, на которой
изменения видно до слияния.

## Почему не GitHub Pages

Pages отдаёт только статические файлы. Форма заявки шлёт данные в
Telegram, а токен бота **нельзя отдавать в браузер** — любой посетитель
открыл бы исходники и забрал бота себе. Значит, нужен серверный
обработчик, и Pages для этого не годится.

На Vercel эндпоинт `/api/lead` выполняется на сервере, токен живёт в
переменных окружения и в браузер не попадает.

Старый workflow `deploy-pages.yml` удалён как нерабочий для этой схемы.

## Первичная настройка (один раз)

Эти шаги выполняет человек — доступа к аккаунтам у Claude нет.

### 1. Бот в Telegram

1. Написать [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Получить **токен** вида `1234567890:AA...`. Это пароль от бота —
   никому не пересылать, в репозиторий не класть.
3. Узнать **chat_id**, куда слать заявки:
   - себе лично — написать [@userinfobot](https://t.me/userinfobot);
   - в группу — добавить туда бота и взять id группы (начинается с `-100`).
4. Один раз написать боту `/start`, иначе он не сможет прислать сообщение.

### 2. Проект на Vercel

1. Аккаунт на [vercel.com](https://vercel.com), войти через GitHub.
2. **Add New → Project**, выбрать репозиторий `Building-site`.
3. **Root Directory** указать `frontend` — иначе Vercel не найдёт проект.
   Фреймворк (Astro) определится сам.
4. В **Settings → Environment Variables** добавить две переменные
   для окружений Production и Preview:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 1.2 |
| `TELEGRAM_CHAT_ID` | id из шага 1.3 |

5. Задеплоить. Vercel выдаст адрес.

### 3. После первого деплоя

- В `frontend/astro.config.mjs` заменить `site` на реальный адрес —
  от него считаются canonical, Open Graph и sitemap.
- Заполнить контакты в `frontend/src/content/site.ts` (см. блок `todo`).

## Локальный запуск

```
cd frontend
npm install
npm run dev
```

Откроется на `http://localhost:4321`.

Чтобы форма локально реально отправляла в Telegram, создать
`frontend/.env` по образцу `frontend/.env.example`:

```
TELEGRAM_BOT_TOKEN=1234567890:AA...
TELEGRAM_CHAT_ID=123456789
```

Файл `.env` в `.gitignore` — в репозиторий он не попадёт.

**Без этих переменных** эндпоинт отвечает `503 not_configured`, а форма
показывает человеку ошибку. Это сделано намеренно: притворяться, что
заявка ушла, нельзя — иначе клиент будет ждать звонка, которого не будет.

## Проверка после настройки

1. Открыть сайт по адресу Vercel.
2. Отправить тестовую заявку через форму.
3. Убедиться, что сообщение пришло в Telegram.
4. Проверить на телефоне: вёрстка не разъезжается, видео на мобильном
   не грузится (только постер).
5. Прогнать навык `test-project`.

## Откат

В панели Vercel: **Deployments** → нужный прошлый деплой →
**Promote to Production**. Занимает секунды и не требует коммитов.

Если нужно откатить сам код — через PR из `dev`, как обычные изменения:
прямой пуш в `main` закрыт защитой ветки и локальным хуком.

## Чего пока нет

- **Своего домена.** Адрес вида `vercel.app` для старта нормален.
- **Хранения заявок.** Заявка уходит только в Telegram. Если сообщение
  не дошло, следа не останется. Когда пойдёт реальный трафик, стоит
  добавить дублирующую запись в базу — заведено в `TODO.md`.
- **Ограничения частоты между инстансами.** Счётчик живёт в памяти
  функции; от массового залива ботами защищает, от распределённой
  атаки — нет. Понадобится жёстче — Upstash Redis.
