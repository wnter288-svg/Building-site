# Деплой

Как код попадает на сайт.

**Адрес сайта:** https://wnter288-svg.github.io/Building-site/

Настраивать ничего не нужно — всё уже работает. Аккаунтов, серверов и
секретов не требуется.

---

## Как это работает

```
  работаем в dev  ──PR──►  main  ──автоматически──►  GitHub Pages
```

Мерджим Pull Request в `main` → GitHub собирает `frontend/` и публикует
результат. Пуш в `dev` на сайт ничего не выкатывает — в этом смысл
разделения веток.

Запустить публикацию вручную: вкладка **Actions** → *Deploy to GitHub
Pages* → **Run workflow**.

Пока в `frontend/` нет проекта, публикуется страница-заглушка. Как только
там появится сборка, публиковаться начнёт она — правок в workflow не
нужно.

## Что где живёт

| Часть | Где работает |
|---|---|
| Фронт (`frontend/`) | GitHub Pages, публично в интернете |
| Бэк (`backend/`) | только локально, `npm run dev` на своей машине |

**Бэкенд в интернет не выкладывается.** GitHub Pages отдаёт только
статические файлы, Node-процесс там запустить негде. Это осознанное
решение: проект учебный, ради тренировки поднимать сервер не стоит.

На практике это значит:
- локально всё работает по-честному — фронт стучится в свой бэк, форма
  отправляет заявку, уведомление приходит;
- на опубликованной странице форма работать не будет, там только вёрстка.

Когда понадобится по-настоящему — бэк переедет на хостинг без переделки
кода. Разобранные варианты лежат в `docs/RECOMMENDATIONS.md`.

## Одна настройка, о которой легко забыть

Сайт живёт **не в корне домена**, а по пути `/Building-site/`. Сборщику
нужно об этом сказать, иначе стили и скрипты будут искаться в корне и
дадут 404 — страница откроется без оформления.

**Astro** (`frontend/astro.config.mjs`):
```js
export default defineConfig({
  base: '/Building-site/',
});
```

**Vite / React** (`frontend/vite.config.js`):
```js
export default defineConfig({
  base: '/Building-site/',
});
```

Локально при этом сайт открывается по адресу
`http://localhost:4321/Building-site/` — так и должно быть.

Workflow ожидает готовую сборку в `frontend/dist` (туда кладут и Astro, и
Vite). Если сборщик настроен на другую папку — поправить путь в
`.github/workflows/deploy-pages.yml`.

## Проверка

1. Вкладка **Actions** — workflow *Deploy to GitHub Pages* зелёный.
2. Открыть https://wnter288-svg.github.io/Building-site/ — там свежая
   сборка. Первая публикация после включения Pages может занять пару
   минут.
3. Открыть на телефоне — вёрстка не разъезжается.
4. Прогнать навык `test-project`.

## Откат

Сломанное уехало на сайт — откатываем коммит в `main`:

```bash
git checkout dev && git pull
git revert <хеш плохого коммита>
git push
gh pr create --base main --head dev --title "Откат"
```

Прямой пуш в `main` заблокирован (branch protection на GitHub +
локальный хук), поэтому откат идёт тем же путём, что и обычные
изменения — через PR. Быстрее всего — кнопка **Revert** на смердженном
PR в веб-интерфейсе GitHub: она сама создаёт готовый PR с откатом.

## Чего здесь пока нет

- **Своего домена.** Адрес вида `github.io` для учебного проекта
  нормален. Понадобится свой — покупаем `.ua`/`.com.ua` и привязываем в
  настройках Pages.
- **Staging-окружения.** Из `main` едет сразу на сайт. Для двоих
  приемлемо.
- **Работающей формы в интернете.** См. выше — бэк только локальный.
