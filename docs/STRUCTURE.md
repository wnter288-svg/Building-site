## Правила структуры

1. **Две зоны, две папки.** Всё фронтовое — в `frontend/`, всё бэковое —
   в `backend/`. Файлы, разбросанные по корню, запрещены: корень только
   для конфигов уровня репозитория и четырёх файлов выше.

2. **Документация только в `docs/`** (кроме README.md, TODO.md и CLAUDE.md
   — они в корне, потому что это точки входа).

3. **Имя папки говорит, что внутри.** `components/`, `pages/`, `routes/`,
   `services/` — понятно. `utils/`, `helpers/`, `common/`, `misc/` —
   свалки, куда складывают то, о чём не подумали. Заводить их без веской
   причины нельзя.

4. **Один файл — одна ответственность.** Если файл перевалил за ~300
   строк и в нём несколько несвязанных вещей — это повод разделить.

5. **Секретов в репозитории нет.** Ключи, пароли, токены — только в
   `.env`, который в `.gitignore`. В репозиторий кладём `.env.example`
   с пустыми значениями, чтобы напарник знал, какие переменные нужны.

6. **Переносишь файлы — обнови этот документ** и импорты в коде, потом
   прогони `/test-project`, чтобы убедиться, что ничего не отвалилось.

## История структурных решений

Зачем: чтобы через полгода никто не переделывал обратно, не понимая, почему
сделано так.

- **2026-09-02** — заведены `docs/` (вся документация), `.claude/skills/`
  (общие навыки), `frontend/` + `backend/` (зоны). Причина: репозиторий
  начинался с одного CLAUDE.md, дальше без разделения зон два разработчика
  начали бы конфликтовать в git.
- **2026-09-02** — введены ветки `dev` (рабочая) и `main` (стабильная),
  перенос только через PR. Причина: не ломать рабочий сайт случайным пушем.
- **2026-09-02** — репозиторий сделан публичным. Причина: на бесплатном
  плане GitHub Pages и branch protection доступны только публичным
  репозиториям, а проект учебный — скрывать нечего.
- **2026-09-02** — отказались от VPS и своего хостинга в пользу GitHub
  Pages. Причина: проект учебный, настройка сервера ради тренировки не
  окупается. Следствие: бэкенд работает только локально.
