## Тимофею от Дани — сделай это до начала работы

**1. Включи хуки (одна команда, один раз):**

```
git config core.hooksPath .githooks
```

Не даст случайно запушить в `main`. Git не подхватывает хуки из
репозитория сам, поэтому команду надо выполнить руками на своей машине.
На GitHub защита ветки тоже включена — PR обязателен, прямой push
отклоняется сервером. Хук просто ловит ошибку раньше и объясняет
понятнее.

**2. Учти базовый путь при настройке сборщика.**

Сайт публикуется на GitHub Pages при мердже PR в `main`:
https://wnter288-svg.github.io/Building-site/

Живёт он **не в корне домена**, а по пути `/Building-site/`. Без этого в
конфиге стили и скрипты дадут 404, страница откроется голой:

```js
// astro.config.mjs (или vite.config.js)
export default defineConfig({
  base: '/Building-site/',
});
```

Сборка должна лежать в `frontend/dist` — туда кладут и Astro, и Vite,
менять ничего не нужно. Подробности в `docs/DEPLOY.md`.

**3. Прочитай, что появилось в репозитории:**

- `docs/PROJECT.md` — цель и границы. **Проект учебный**: реального
  заказчика нет, компанию и данные выдумываем сами. Тренируемся на
  лендинге строительной компании, делаем его как настоящий.
- `docs/MVP.md` — объём первой версии, твои блоки по фронту отмечены.
- `TODO.md` — задачи, твои помечены `[Т]`.
- `docs/STRUCTURE.md` — карта репозитория и правила раскладки.
- `docs/DEPLOY.md` — как код попадает на сайт.
- `.claude/skills/` — 4 общих навыка, твой Claude Code подхватит сам:
  `project-docs`, `project-structure`, `test-project`, `advisor`.

Ещё: бэкенд в интернет не выкладывается, он только локальный. Форма на
опубликованной странице работать не будет — это ожидаемо. Локально всё
работает по-честному.
